# ADR-002: Shared PostgreSQL With RLS As Default Tenancy

## Status

Accepted

## Context

The previous architecture considered shared database, schema-per-tenant, and database-per-tenant. Supporting all three early would create heavy operational complexity.

## Decision

Default tenancy is shared PostgreSQL with `tenant_id`, PostgreSQL Row-Level Security, tenant-aware indexes, and application-level tenant guards.

Schema-per-tenant and database-per-tenant are not default product tiers. They require a separate enterprise ADR.

## Consequences

Benefits:

- Simpler operations.
- Easier migrations.
- Easier analytics.
- Lower cost.
- Strong enough isolation when RLS and tests are done correctly.

Trade-offs:

- Large tenants may require future sharding.
- RLS must be implemented carefully with connection pooling.
- Tenant isolation tests are mandatory.

## Rules

- Every tenant-owned table includes `tenant_id`.
- RLS must be enabled before production use.
- Tenant context must be transaction-scoped.
- Support bypass must be explicit, time-bound, and audited.
