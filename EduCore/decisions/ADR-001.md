# ADR-001: Start With Modular Monolith

## Status

Accepted

## Context

EduCore has many domains: identity, tenancy, academics, finance, payments, notifications, AI, offline sync, and analytics. Starting with microservices would add distributed systems complexity before product-market fit.

## Decision

EduCore will start as a NestJS modular monolith with strict bounded contexts and module boundaries.

## Consequences

Benefits:

- Faster MVP delivery.
- Lower infrastructure cost.
- Easier debugging.
- Easier transaction management.
- Better fit for small engineering team.

Trade-offs:

- Some modules cannot scale independently at first.
- Boundary discipline must be enforced in code and CI.
- Future extraction requires stable interfaces and events.

## Rules

- Modules communicate through public interfaces or domain events.
- No direct cross-module table access.
- Use transactional outbox for domain events.
- Extract services only when scaling, ownership, or reliability demands it.
